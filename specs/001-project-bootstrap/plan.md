# Implementation Plan: Project Bootstrap

**Branch**: `001-project-bootstrap` | **Date**: 2026-05-29 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `specs/001-project-bootstrap/spec.md`

## Summary

Ship the foundational, runnable shell of Pub/Sub Dashboard: a single-process
Node application invokable via `npx pubsub-dashboard` that boots a loopback
HTTP server on port `4321` in under 3 seconds (warm cache), resolves the active
GCP project by shelling out to `gcloud config get-value project`, validates
ADC, opens the user's browser onto a minimal dashboard that displays the
project + identity + a diagnostics panel, and ships behind a CI pipeline that
enforces the full Spec Kit quality gate set (ESLint, Prettier, `tsc --noEmit`,
Vitest ≥90% line+branch on `src/**`, Playwright smoke of the cold-boot path,
and a CI-validated README quickstart) on `ubuntu-latest` and `macos-latest`.

Bootstrap deliberately leaves a documented extension surface (FR-020) for the
publish/subscribe/JSON-compose features that follow in later `/speckit.specify`
cycles, and ships zero remote-network surface beyond Google Cloud APIs.

## Technical Context

**Language/Version**: TypeScript 5.6+, Node.js ≥ 20 LTS

**Primary Dependencies**:

- Server: `hono` (router/middleware), `google-auth-library` (ADC resolution + userinfo lookup), `pino` (structured logging), `zod` (shared schemas), `open` (browser launch). **Note**: `@google-cloud/pubsub` is intentionally NOT a v1 runtime dependency — it lands with feature 002 (publish/subscribe). See `research.md` R2 + R13 for rationale.
- Client: `react@18`, `react-dom@18`, `vite`, `@vitejs/plugin-react`, `tailwindcss`, `@radix-ui/*` via `shadcn/ui` primitives, `lucide-react`
- Tooling: `vitest`, `@vitest/coverage-v8`, `@playwright/test`, `eslint`, `@typescript-eslint/*`, `prettier`, `tsx` (dev runner)

**Storage**: A single JSON preferences file at `~/.config/pubsub-dashboard/preferences.json` (created lazily on first write; not touched at all during bootstrap v1 — the path is reserved by FR/entities but no preference is persisted yet). No database.

**Testing**:

- Unit + integration: `vitest` with `@vitest/coverage-v8`, threshold ≥90% line and branch on `src/**`. Excludes (declared in `vitest.config.ts`): `bin/**`, `*.d.ts`, generated code, story files, pure presentational React components in `src/client/components/ui/**` (shadcn primitives).
- E2E smoke: `@playwright/test` running the headless API surface only (no browser window) — boots the assembled production server via the same code path as the `npx` bin, hits `/api/health` and `/api/session`, verifies CSP headers, and verifies loopback-only bind.
- README quickstart validation: a CI job that executes the README's "Quickstart" block verbatim (extracted by a small script) and fails on non-zero exit.

**Target Platform**: macOS (Apple Silicon + Intel) and Linux x64/arm64, Node ≥ 20 LTS, served on `127.0.0.1:4321` (override via `--port <n>`). Windows is explicitly out of scope for v1.

**Project Type**: Single-process Node web app (Hono server + Vite-built React static client bundled and served by the same process). Distributed via npm with a `bin` entry.

**Performance Goals**:

- Cold-boot (warm npm cache) → dashboard interactive in browser: **< 3 s at p95** (SC-001).
- First authenticated API call after interactive: **< 1 s** (SC-002).
- Clean shutdown on SIGINT/SIGTERM: **< 1 s** (FR-004).
- Bundle size: client bundle < 200 KB gzipped (internal target — not in spec but supports SC-001).

**Constraints**:

- Bind exclusively to `127.0.0.1`; no `0.0.0.0` ever.
- Zero outbound traffic outside Google Cloud API endpoints; no telemetry, analytics, or update-check.
- Strict Content-Security-Policy on every HTML response; no third-party CDN assets.
- No credentials or raw payloads logged in normal mode.
- `gcloud` CLI MUST be available on `PATH` at runtime.
- 90% line + branch coverage on `src/**` is a hard CI gate.

**Scale/Scope**: Single developer, single concurrent session, single GCP project per run. v1 surface is intentionally small: project + identity badge, diagnostics panel, health endpoint — the full publish/subscribe/compose flows are deferred to future features.

## Constitution Check

*GATE: Must pass before Phase 0 research. Re-check after Phase 1 design.*

Verify the plan against each principle in `.specify/memory/constitution.md`:

- **I. Local-First & Zero-Config** — ✅ Plan binds Hono to `127.0.0.1:4321` only (Technical Context: Target Platform). No remote backend; no telemetry; first run requires only `gcloud auth application-default login` + `gcloud config set project <id>`. `npx` is the only install/run command.
- **II. Test-First (NON-NEGOTIABLE)** — ✅ Plan schedules failing tests before implementation (see Phase 2 ordering in `tasks.md` to be generated by `/speckit.tasks`). Vitest threshold ≥90% line+branch on `src/**` with the *exact* exclusion list from FR-015 wired into `vitest.config.ts`. Playwright smoke covers the cold-boot path of the `npx` bin (FR-016). README quickstart is CI-validated (FR-019).
- **III. Type Safety End-to-End** — ✅ TypeScript `strict: true` + `noImplicitAny` + `strictNullChecks` + `noUncheckedIndexedAccess` in a single root `tsconfig.json` extended by `tsconfig.server.json` and `tsconfig.client.json`. All request/response shapes defined as `zod` schemas in `src/server/schemas/**` and imported by both server (validation) and client (typed fetch). `tsc --noEmit` is a blocking CI gate.
- **IV. Instant DX (One-Command UX)** — ✅ `npx pubsub-dashboard` is the documented one-command first run. Bin entrypoint performs Node-version guard, parses `--port`, boots server, opens browser via `open`. All error paths produce a single copy-pastable remediation line (auth/project resolution mapped to specific `gcloud` commands). README "Quickstart" is exercised by a dedicated CI job on every PR (FR-019).
- **V. Operational Excellence** — ✅
  - Observability: `pino` JSON logs with per-request trace IDs; `--verbose` flag raises level to `debug`; in-UI Diagnostics panel exposes the raw last request/response.
  - Security: `gcloud` ADC only (no key files, no env-var tokens); payloads redacted in logs in normal mode; strict CSP; loopback bind; zero non-Google outbound.
  - Simplicity: no DB; prefs file reserved but unused in v1; new runtime dependencies are limited to those justified in the dependency table of `research.md`.

**Structure Decision**: Single TypeScript project (no monorepo, no separate
server/client packages). Justification: the constitution locks the stack to
*one Node process* in production; an extra package boundary buys nothing and
adds tooling friction for a v1 with ~2k LOC. Schemas are shared by direct
import from `src/server/schemas/` — both client and server resolve them via
the same `tsconfig.json` `paths`.
